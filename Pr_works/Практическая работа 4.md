Вопросы:
**В чем принципиальная разница между "адаптивным дизайном" (adaptive) и "отзывчивым дизайном" (responsive) веб-страниц, и какой из подходов реализуется с помощью медиа-запросов в данной работе?**  

Адаптивный дизайн использует несколько фиксированных макетов, которые переключаются при определённой ширине экрана. Отзывчивый дизайн плавно подстраивается под любую ширину, потому что элементы тянутся и перестраиваются гибко.

**Объясните, как браузер интерпретирует медиа-запросы. Что произойдет, если для устройства с шириной экрана 750px будут одновременно активны  два  медиа-запроса: (max-width:  600px) и (min-width: 768px) и (max-width: 959px)?**   

Браузер читает CSS сверху вниз и проверяет каждое условие медиа-запроса. Если условие истинно, стили внутри него применяются. При ширине 750px запрос max-width 600px не сработает, потому что 750 больше 600. Запрос min-width 768px и max-width 959px тоже не сработает, потому что 750 меньше 768. В итоге не применится ни один из этих двух запросов, и страница будет использовать базовые стили.

**В работе предложены жесткие значения ширины экрана (600px, 768px, 1280px). Почему на практике все чаще используют подход "Mobile First" с min-width, а не "Desktop First" с max-width?**  

Подход Mobile First означает, что сначала пишутся стили для мобильных устройств, а потом через min-width добавляются стили для более широких экранов. Это удобнее, потому что мобильный трафик сейчас больше, код получается чище, а базовые стили остаются лёгкими. Кроме того, так проще избежать конфликтов, когда стили для десктопа случайно применяются на телефоне.  

**Проанализируйте приведенный HTML-код с блоками .qw. Как медиа-запросы влияют на визуальное представление блоков при изменении размера экрана?**  
В примере медиа-запросы меняют порядок блоков через свойство order и скрывают некоторые блоки через display: none. На широком экране блоки идут в одном порядке, на среднем экране порядок меняется, а на узком часть блоков скрывается, чтобы интерфейс стал проще и не перегружал маленький экран.

**В примере с блоками используется свойство order для изменения их очередности. Приведите пример реального интерфейса, где изменение порядка блоков на мобильных устройствах критически важно для удобства пользователя.**  
На сайте интернет-магазина на мобильном устройстве блок с ценой и кнопкой «Купить» должен идти сразу после названия товара, а не после длинного описания и отзывов. На десктопе порядок может быть другим, но на телефоне пользователь должен быстро увидеть цену и кнопку покупки, иначе он уйдёт.

**В коде блоки скрываются с помощью display: none. Почему скрытие элементов на мобильных устройствах может не дать существенного выигрыша в производительности загрузки, если не применять дополнительные техники?**  
Потому что элемент всё равно загружается браузером, просто не отображается на экране. Если это тяжёлая картинка или скрипт, трафик всё равно расходуется, и время загрузки не уменьшается.  

**Какую технику из первой лабораторной работы (или ее развитие) следует применить к изображениям, чтобы они корректно и быстро загружались на мобильных устройствах с разной плотностью пикселей (Retina-экраны)?**  
Нужно использовать атрибут srcset с несколькими версиями изображения разного разрешения и атрибут sizes. Браузер сам выберет подходящий файл в зависимости от ширины экрана и плотности пикселей. Это позволяет не загружать тяжёлые картинки на обычных экранах и отдавать качественные изображения на Retina-экранах.  

**В шаге 3 упоминаются иконочные шрифты. В чем преимущество использования иконочных шрифтов (или SVG-иконок) перед использованием растровых изображений (PNG) для маленьких элементов интерфейса с точки зрения адаптивности и производительности?**  
Иконочные шрифты и SVG являются векторными, поэтому они масштабируются без потери качества. Они весят меньше, чем растровые PNG, их можно менять по цвету и размеру через CSS, и они лучше подходят для адаптивного дизайна.  

**Для работы примера используется тег <meta name="viewport" content="width=device-width, initial-scale=1.0">. Что произойдет с отображением адаптивного макета, если удалить этот тег? Объясните физический смысл его атрибутов.**  
Мобильный браузер будет считать, что страница предназначена для десктопа, и отобразит её в уменьшенном масштабе. Пользователю придётся увеличивать страницу пальцами, чтобы прочитать текст, а медиа-запросы могут сработать неправильно.  

**В работе предлагается тестировать на реальных устройствах. Назовите два способа эмуляции мобильных устройств, доступных в браузерах (например, Chrome DevTools), и укажите, в чем главное ограничение такого эмулятора по сравнению с реальным физическим устройством.**  
Первый способ это режим устройства в Chrome DevTools, который вызывается по F12. Второй способ это расширения вроде User-Agent Switcher. Главное ограничение эмулятора в том, что он не передаёт реальные характеристики устройства: скорость интернета, особенности сенсорного ввода, реальную плотность пикселей и поведение при повороте экрана.
