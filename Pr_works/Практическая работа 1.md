как браузер параллелит запросы;

На практике браузер делегирует все сетевые запросы своему внутреннему движку, который работает параллельно с основным потоком JavaScript. Когда вы вызываете fetch() для трёх постов, браузер мгновенно отправляет их все, не дожидаясь ответа по каждому. При HTTP/2 они летят по одному соединению одновременно, а при HTTP/1.1 — распределяются по нескольким отдельным каналам. Ответы, по мере поступления, попадают в очередь событий, и главный поток обрабатывает их по очереди, когда освободится, при этом отдавая приоритет более срочным задачам, например, прокрутке страницы, нет ли избыточных запросов.
Все они являются избыточными запросами, так как можно оптимизировать и создать один запрос, выводящий нужную информацию.

Контрольные вопросы  
1. Что такое DevTools и какие задачи решают вкладки Elements, Console и Network?  
DevTools - это встроенные в браузер инструменты разработчика, которые позволяют анализировать, отлаживать и оптимизировать веб-страницы в реальном времени.  
Вкладка Elements - показывает структуру DOM-дерева страницы и применяемые CSS-стили. Позволяет редактировать HTML и CSS, просматривать изменения сразу на странице, проверять адаптивность и отлаживать вёрстку.  
Вкладка Console - служит для вывода логов и ошибок JavaScript, а также для выполнения произвольного кода в контексте текущей страницы. Используется для отладки скриптов, проверки значений переменных и экспериментов с API. 
Вкладка Network - анализирует все сетевые запросы, которые отправляет страница: методы, URL, заголовки, размер данных, время загрузки и статус-коды. Помогает выявлять медленные запросы, оптимизировать загрузку ресурсов и проверять корректность API-взаимодействий.  
2. Как открыть DevTools и какие настройки вкладки Network важны для замеров производительности?  
Способы открытия DevTools:  
-	Клавиша F12 (основной способ)  
-	Сочетание Ctrl+Shift+I (Windows/Linux) или Cmd+Option+I (Mac)  
-	Правый клик по странице → "Просмотреть код"  
-	Через меню браузера: "Дополнительные инструменты" → "Инструменты разработчика"  
Важные настройки вкладки Network для замеров:  
-	Disable cache - отключает кэширование браузера, чтобы получить реальное время загрузки без использования сохранённых копий.  
-	Throttling - симуляция скорости интернета (Online, Slow 3G, Fast 3G, 4G) для проверки производительности при разных условиях сети.  
-	Preserve log - сохраняет логи запросов при перезагрузке страницы или навигации, чтобы не потерять историю.  
-	Recording - кнопка записи (красная точка) для включения/отключения отслеживания запросов.  
3. Перечислите основные части HTTP-запроса и их назначение  
1. Метод (HTTP Method)  определяет действие, которое клиент хочет выполнить над ресурсом:  
•	GET - получить данные  
•	POST - создать данные  
•	PUT - полностью обновить  
•	PATCH - частично обновить  
•	DELETE - удалить  
2. URL и параметры  адрес ресурса, к которому обращается клиент. Параметры могут быть:  
•	В пути (path): /users/5 (идентификатор ресурса)  
•	В строке запроса (query): ?page=2&limit=10 (фильтрация, пагинация)  
3. Заголовки (Headers) - метаданные запроса:  
•	Content-Type - формат данных в теле  
•	Authorization - токен для аутентификации  
•	Accept - какой формат данных ожидает клиент  
•	Cache-Control - управление кэшированием  
•	User-Agent - информация о браузере/устройстве  
4. Тело запроса (Body) - передаваемые данные (для POST, PUT, PATCH). Содержит информацию для создания или обновления ресурса, обычно в формате JSON, XML или form-data.
    
4. Чем отличаются методы GET, POST, PUT, PATCH и DELETE? Приведите примеры  
Метод GET получает данные с сервера, не меняя их. Параметры передаются в URL, запрос кэшируется. Пример: открытие страницы товара.  
Метод POST создаёт новый ресурс, данные идут в теле запроса. Пример: регистрация пользователя или отправка комментария.  
Метод PUT полностью заменяет ресурс целиком, нужно передать все поля. Пример: обновление профиля со всеми данными  имя, email, телефон.  
Метод PATCH частично обновляет ресурс, меняет только указанные поля. Пример: смена только email, остальные данные не трогаются.  
Метод DELETE удаляет ресурс с сервера. Пример: удаление поста или товара из корзины.  
5. Для чего используются методы HEAD и OPTIONS и где встречается preflight-запрос?  
HEAD - запрашивает только заголовки ответа без тела.   
Используется для: проверки существования ресурса, получения информации о размере файла (Content-Length), проверки даты последнего изменения (Last-Modified), проверки доступности ресурса без загрузки данных
OPTIONS - запрашивает информацию о поддерживаемых методах для указанного ресурса.   
Используется для: проверки, какие методы разрешены сервером (GET, POST, PUT, DELETE и т.д.), определения доступных заголовков и CORS-политик  
Preflight-запрос - это OPTIONS-запрос, который браузер автоматически отправляет перед "сложными" CORS-запросами (не GET/POST с простыми заголовками).   
Встречается в:  
использовании нестандартных заголовков (например, Authorization, X-Custom-Header);  
использовании методов кроме GET, POST, HEAD (например, PUT, DELETE, PATCH);  
отправке данных в формате, отличном от application/x-www-form-urlencoded, multipart/form-data или text/plain (например, application/json).  
6. Расскажите о группах кодов ответов (1xx-5xx) и приведите примеры  
1xx - Информационные: Запрос получен, обработка продолжается.  
100 Continue  сервер получил заголовки, клиент может отправлять тело
   
2xx - Успешные: Запрос выполнен успешно.  
200 OK - стандартный успешный ответ (например, GET /users)  
201 Created - ресурс создан (после POST)  
204 No Content - запрос выполнен, но ответ не содержит тела (после DELETE)  

3xx - Перенаправления: Клиенту нужно выполнить дополнительные действия.  
301 Moved Permanently  ресурс окончательно перемещён на новый URL  
302 Found - ресурс временно доступен по другому адресу (редирект)  
304 Not Modified - ресурс не изменился, можно использовать кэшированную версию  

4xx - Ошибки клиента: Запрос содержит ошибку со стороны клиента.  
400 Bad Request - неверный синтаксис запроса  
401 Unauthorized - требуется аутентификация  
403 Forbidden - доступ запрещён (недостаточно прав)  
404 Not Found - ресурс не найден  
405 Method Not Allowed - метод не поддерживается для данного ресурса  

5xx - Ошибки сервера: Сервер не смог обработать корректный запрос.  
500 Internal Server Error - внутренняя ошибка сервера  
502 Bad Gateway - ошибка шлюза (прокси-сервер не получил ответ)  
503 Service Unavailable - сервер временно недоступен (перегрузка, техобслуживание)  
504 Gateway Timeout - превышено время ожидания от вышестоящего сервера  

8. Что такое REST и как ресурс в REST представлен на уровне URL?  
REST (Representational State Transfer) – это архитектурный стиль построения веб-API, основанный на принципах клиент-серверного взаимодействия, отсутствия состояния (stateless), кэшируемости и единообразного интерфейса. 
В REST каждый ресурс имеет уникальный адрес (URL), по которому к нему можно обратиться. Для фильтрации и пагинации (разбиение большого объёма данных на отдельные страницы) используются параметры строки запроса, например /posts?userId=1&_limit=10. При этом в URL используются существительные во множественном числе, а действие определяется HTTP-методом.  
9. Какие типы данных поддерживает JSON? Приведите примеры  
JSON (JavaScript Object Notation) поддерживает следующие типы данных:  

| Тип     | Описание                           | Пример                  |
| ------- | ---------------------------------- | ----------------------- |
| Строка  | Текст в двойных кавычках           | "Hello, World!"         |
| Число   | Целые и дробные числа              | 42, 3.14, -10           |
| Булевое | true или false                     | true, false             |
| Null    | Пустое значение                    | null                    |
| Объект  | Набор пар ключ-значение в {}       | {"name": "John", "age”} |
| Массив  | Упорядоченный список значений в [] | [1, 2, 3], ["a", "b"]   |

9. В чём отличие вкладок Preview и Response в карточке запроса DevTools?  
Вкладка Preview отображает данные в удобочитаемом и структурированном виде: JSON показывается как раскрывающееся дерево с подсветкой, изображения выводятся как превью, а HTML – как приближённый рендеринг страницы.   
Вкладка Response показывает сырые данные ровно в том виде, в каком они пришли от сервера: JSON – как обычный текст без форматирования, HTML – как исходный код. Preview удобнее для быстрого визуального анализа структуры ответа, а Response – для точного копирования данных или проверки их исходного формата.

11. Какие приёмы снижения нагрузки на сеть можно использовать для API: пагинация, фильтрация, кэширование и др.?  
Пагинация, фильтрация, сортировка, выборка только нужных полей, кэширование на клиенте и сервере, сжатие данных (gzip, brotli), объединение нескольких запросов в один (batching), использование HEAD-запросов для проверки изменений, ленивая загрузка (lazy loading) и предзагрузка (prefetching).  
12. Чем работа с API в Postman отличается от анализа запросов в DevTools, и когда уместен каждый инструмент?  
DevTools анализирует реальные запросы, которые браузер отправляет при работе с сайтом, автоматически подставляя куки и токены, и показывает полную картину загрузки страницы, включая производительность и кэширование.   Postman позволяет вручную конструировать любые запросы к API вне контекста сайта, сохранять их в коллекции, писать автотесты, работать с переменными окружения и авторизацией, а также генерировать код на разных языках.   
DevTools уместен для отладки фронтенда, анализа реального трафика, проверки кэширования и производительности страницы. Postman нужен для разработки и тестирования API, написания автотестов, документирования и демонстрации примеров, а также когда требуется изолированно проверить работу сервера без участия браузера и фронтенда.
